# T1-WBC 项目计划

> 版本 v1.1　　定版日期 2026-11-02
> 本文件记录"做什么、为什么这样做"。逐文件的"怎么做"见 `docs/modules/`，进度见 `docs/PROGRESS.md`。

## 1. 目标

让机器人从"示教回放"升级为"自主、协同、柔顺、安全"的全身控制系统：

1. **并行准备**：底盘移动途中完成出壁仓、取刷头等准备动作，底盘到位即开始清扫。
2. **偏差补偿**：机械臂实时补偿底盘的位姿误差和扰动。
3. **全身协同**：机械臂与底盘协同清扫，机械臂够不到时底盘自动辅助。
4. **全程可观测**：所有数据可视化，有日志、有曲线。
5. **安全**：不撞墙，不伤人，具备碰撞检测和柔顺停止。
6. **智能清扫**：可指定区域清扫，也可由摄像头识别脏区后自主清扫。
7. **恒力接触**：清扫时刷头以期望压力贴合表面，并自动适应表面倾角。

## 2. 硬件基线

| 项目 | 规格 |
|---|---|
| 底盘 | 前驱差速，2 个驱动轮 + 4 个万向轮；轮径 0.0655 m；轮距 0.406 m（URDF 值，待实测） |
| 机械臂 | 6 关节：J1、J2 平面二连杆（绕 z）；J3 丝杠 z 向平移；J4 绕 z；J5、J6 竖直平面俯仰二连杆 |
| 电机 | 达妙，MIT 模式：`τ = kp(q_des − q) + kd(dq_des − dq) + τ_ff` |
| 末端 | 六维力传感器 + 圆形刷头（不旋转、无电机、轴对称），磁吸装卸 |
| 传感器 | 激光雷达、IMU、深度相机、轮速编码器、六维力传感器 |
| 计算 | Jetson Orin Nano（JetPack 6 / Ubuntu 22.04）；开发机 x86_64 |
| 通信 | 达妙官方 USB-CAN |
| 模型 | `washcar-simulator/v6_description/urdf/6-8-1.urdf`（原样存于 `config/urdf/raw/`） |

**由构型得出的结论**

- 刷头轴对称 → 末端任务是 5 维：位置 3 维 + 刷头轴线指向 2 维（绕轴滚转无关）。
- 机械臂 6 个关节 + 底盘 2 个输入，8 个输入完成 5 维任务，冗余用 QP 权重分工。
- J1、J2、J4 转轴竖直，基本不受重力；J3 重力由丝杠承担 → 重力补偿主要针对 J5、J6。
- J3 丝杠不可反驱 → z 向接触力只能靠力传感器，不能靠电流估计。
- 只有 J5、J6 的俯仰能改变重力在力传感器系中的方向 → 重力辨识要在大俯仰范围内取姿态。

## 3. 系统架构

```text
任务层 task            行为树                               事件 / 10Hz
  │ 任务目标
规划层 planning        底盘 Nav2；机械臂动作库 + 时间参数化；覆盖路径      1–10Hz
  │                       【全局避障】
  │ msgs/TaskSpaceTrajectory（odom 系，带时间戳）
  ▼
┌──────────────────── controller_manager 实时线程，500Hz ────────────────────┐
│ T1::wbc::WbcRosController（唯一的闭环计算拥有者）                              │
│   读状态接口 → 状态估计(estimation) → 力传感器补偿与接触检测(signal)        │
│   → 接触阶段 + 导纳（修正参考）→ 任务与约束 → QP(ProxSuite)                  │
│   → MIT 指令 + 轮速指令                         【实时避障：M5 加距离约束】    │
│ joint_state / imu / ft 广播器                                                │
└────────────────────────────────┬────────────────────────────────────────────┘
                                 │ ros2_control 接口（ros2_control.xacro 定义）
          T1::sim::SimSystem（MuJoCo）  或  T1::hal::HardwareSystem（达妙 CAN）
                                          【安全兜底：看门狗、柔顺停止】
旁路：robot_state_publisher、Rerun（`tools/rerun_view.py`）、foxglove_bridge、rosbag2(mcap)、ros/ft_calibration
```

### 3.1 关键设计决策

| 决策 | 原因 |
|---|---|
| 分解、避障、跟踪三层合并为一个 QP | 分层后各层互相打架；冗余分配必须在同一个优化里做 |
| QP 决策变量用底盘 `[v, ω]` 而不是平面三维速度 | 差速底盘"不能横移"的约束天然满足，问题更小 |
| 估计、力补偿、WBC 都在同一个 500Hz 控制器里 | 避免话题跳转带来的延迟和数据不同步；算法仍各自独立成库，可单测 |
| WBC 工作在 odom 系；map 系定位不进 EKF | 定位校正会跳变，跳变会让机械臂抖；map→odom 由定位模块单独发布 |
| 姿态任务用"刷头轴线指向"（2 维），不用 yaw/pitch 角 | 圆刷绕轴滚转无意义；避免欧拉角奇异 |
| 仿真和实机都实现为 ros2_control 硬件插件，接口契约写在 `ros2_control.xacro` | 上层代码一行不改即可切换 |
| 机械臂接口：position / velocity / effort / stiffness / damping | 一一对应 MIT 模式的 q、dq、τ_ff、kp、kd |
| 仿真里 MIT 力矩在每个物理步重算 | 模拟电机内部的高频 PD 回路 |
| 刷头参数随刷头切换，存在 `brushes.yaml` | 不同刷头质量和质心不同，用错会产生几牛的假接触力 |
| 控制器从 robot_state_publisher 取 URDF | Humble 的控制器拿不到 controller_manager 的 robot_description |
| ProxSuite / MuJoCo 在实现对应文件时才链接 | 框架阶段就能编译通过；依赖装好后在 CMake 里放开一行即可 |

### 3.2 避障分三层

1. **规划层（全局）**：墙、柜子、壁仓等大型静态障碍，用代价地图和三维距离场。（M4）
2. **WBC（实时）**：自碰撞、机械臂与环境、底盘与障碍，写成 QP 的速度阻尼器约束 `ḋ ≥ −ξ(d − d_s)/(d_i − d_s)`。（M5，文件 `constraint_collision`）
3. **电机层（兜底）**：力突变或动量观测器残差超限 → `kp = 0` 柔顺停止；有人靠近按距离降速；通信中断进入阻尼模式。（M5/M8）

### 3.3 力传感器与导纳

- 读数模型（传感器系）：`F_s = F_ext + m·g_s + F_b`，`τ_s = τ_ext + c × (m·g_s) + τ_b`，10 个参数线性最小二乘辨识。
- 处理链：零偏与重力 → 惯性（可选）→ 二阶低通 → 外力。
- 每次接触前在空中重新标零；换刷头后加载对应参数，可在底盘匀速段做俯仰扫描复核。
- 刷头脱落检测：补偿后在无接触时出现约 `+m·g` 向上的力。
- 导纳：法向 `M·a + D·v + K·x = F_meas − F_des`（K = 0 为纯力跟踪）；倾斜方向用接触力矩让刷头贴合表面。
- 接触三阶段：接近（低速沿法向靠近直到检测到接触）→ 清扫（期望力斜坡上升后恒力）→ 离开（力斜坡降到 0 再抬起）。

## 4. 里程碑

| 里程碑 | 内容 | 验收标准 |
|---|---|---|
| M0 建模与仿真 | 整理 xacro；生成 MJCF；MuJoCo 硬件插件；运动学基础；可视化与录包 | 遥控底盘、单关节控制在 Foxglove 中可见；Pinocchio 与 MuJoCo 正运动学误差 < 0.1 mm；新机器上 `check_env.sh` 全过 |
| M1 运动学 WBC | 末端 5 维跟踪 + 姿态任务 + 底盘任务 + 限位 + QP + MIT 指令 | 遥控底盘时刷头世界系位置误差 < 5 mm；目标走远时底盘自动跟随 |
| M2 状态估计 | 轮速里程计 + 陀螺仪 EKF；仿真注入噪声、打滑 | 有扰动时 M1 指标仍成立 |
| M3a 力传感器补偿 | 仿真力传感器（零偏、噪声）；辨识、补偿、标零、刷头参数 | 空中任意俯仰运动时补偿后残余力 < 0.5 N |
| M3b 导纳与接触 | 接触三阶段、法向恒力、倾斜贴合、脱落检测；实验确定清扫力 | 底盘移动中，平面和斜面上恒力误差 < ±20%；确定清扫力取值 |
| M4 规划层 | Nav2、机械臂动作库、时间参数化、覆盖路径 | 给定区域后自主前往并完成往返清扫 |
| M5 避障与安全 | 碰撞距离约束、安全兜底、无解时重规划 | 障碍突现时避让或停止；人靠近降速；碰撞后柔顺停止 |
| M6 任务层 | 行为树、并行准备、按到达时间倒排 | 一条命令完成全流程；到位后等待 < 1 s |
| M7 视觉清扫 | 脏区分割 → 区域 → 覆盖清扫 | 识别出脏区后自动清扫 |
| M8 实机 | 达妙驱动、CAN 实测、系统辨识、力传感器实机标定 | 按 M1→M7 顺序在实机上复现 |
| M9 可选 | 动力学 MPC（acados）、自适应力控 | 高速与接触切换性能优于 WBC 基线 |

硬件驱动（`hal/`）建议从 M1 起并行开发。

## 5. 环境与部署

### 5.1 版本基线（`scripts/versions.sh` 是唯一来源）

| 依赖 | 版本 | 来源 |
|---|---|---|
| Ubuntu / ROS 2 | 22.04 / Humble | apt |
| GCC | 11 | 系统；交叉编译器 Buildroot 2022.08 GCC 11.3 |
| Pinocchio / hpp-fcl | 2.7.0 / 2.4.4 | x86：robotpkg（apt pin + hold）；Jetson：源码编译。均在 `/opt/openrobots` |
| ProxSuite | 0.7.3 | 同上 |
| MuJoCo | 3.9.0 | C 库官方压缩包 `~/.mujoco/mujoco-3.9.0`；Python 包同版本 |
| Rerun | 0.35.0 | `rerun-sdk`，可视化。声明依赖 numpy 2，安装时 `--no-deps`，与钉死的 numpy 1.26.4 共存 |

**已知情况**
- 本机同时装有 `ros-humble-pinocchio`（3.9.0）。`env.sh` 保证 `/opt/openrobots` 排在 `/opt/ros/humble` 前面，`T1Pinocchio.cmake` 发现 3.x 会直接报错。
- CMake 会提示 urdfdom 在系统和 ROS 目录各有一份（同为 3.0 版本），属于无害警告。

### 5.2 脚本

| 脚本 | 作用 |
|---|---|
| `scripts/setup_deps.sh` | x86 一键安装与锁版本（不要整份 sudo；脚本内部会对 apt 提权） |
| `scripts/setup_deps_jetson.sh` | Jetson 一键安装，Pinocchio/hpp-fcl/ProxSuite 源码编译 |
| `scripts/env.sh` | 每个终端 source：ROS → `/opt/openrobots` → MuJoCo → 工作空间 |
| `scripts/check_env.sh` | 只读自检 |
| `tools/sync_sysroot.sh` | 从 Jetson 同步交叉编译 sysroot |
| `tools/deploy.sh` | 交叉编译后部署；`--remote-build` 改为在 Jetson 上编译 |

**交叉编译的风险**：ROS 包的交叉编译（rosidl 代码生成、ament 工具链）需要在 M0 实际验证。如果不顺，用 `deploy.sh --remote-build` 在 Jetson 上原生编译作为兜底。

### 5.3 计算与实时
- controller_manager 线程绑核、SCHED_FIFO；评估 PREEMPT_RT 内核。
- `WbcStatus` 发布每周期耗时，监控 P99 与超时次数。
- CAN 预算：经典 CAN 1 Mbps 下 6 个电机一发一收约 1560 bit/周期，500 Hz 负载约 78%。机械臂电机分两路 USB-CAN，底盘独立通道。
